# 福船 r6：艉部、舵叶与甲板观感精修

2026-10-26。续作基于r5真实审阅结果；目标仍是完成有艺术审美的可驾驶海战游戏，当前只推进用户优先指定的主角船。整场性能、海岛氛围与玩法仍未完成。

## 这次实际改变

- 艉墙：约68%中央主面、两侧折角向前收0.32m；补厚角柱、压边、四块承托膝材与尾护栏，中央留舵杆开口。
- 舵叶：楔形厚度、圆收脚、后掠肩部；保留原轴、舵杆、舵柄和握点。r6-a在0.48rad余量检查中1次擦艉，r6-b后收上肩后通过三向检查；实际游戏极限为0.42rad。这里不把余量失败说成实际操作极限必然失败。
- 两舷8窗：墙面真实开洞，暗底位于框后；三LOD射线证明凹深大于0.06m。后横墙两窗仍为封闭暗色窗面/框层次，并非贯通孔。
- 舵铁带和铆钉合并为一个网格；节点总数由r6-a的104降为81，r5为82。
- 主甲板：16mm物理缝造成航行距离黑点；同镜头16/4/0mm独立诊断后采用4mm细缝。保留木板层次，未改生成贴图像素。

当前源：assets/production/hero-fuchuan-blender/hero-fuchuan-v3-r6.blend；GLB：assets/models/hero_fuchuan_v3_r6。r5原件与GLB保留，r6-a/b源与原帧也保留。重建：RTK包装Blender，运行tools/blender/build_hero_fuchuan_v3.py -- --refine-stern --review-run=新唯一名称。默认与实验室选择已切到art_r6；art仍可回看r5。

导出总三角LOD0/1/2：110,793 / 53,653 / 31,057；各含1,614个隐藏投影资源三角，可见为109,179 / 52,039 / 29,443。可见LOD0较r5增加约7.8%，未提高投影细分。

## 保留的限制与取舍

Ruling: c版允许主甲板几何字节变化，以真实4mm拼缝降低空间采样黑点；原b版“deck逐字节相同”结论不用于c版。代价是基线不能再做全部几何完全相同声明，故增加接缝测量和原支撑回归。

Ruling: 新舵叶YZ投影约5.989m²，较旧6.3745m²少6.04–6.05%，略超brief“尽量±5%”。为肩部避让和轮廓保留此差异；游戏操舵权威不读取显示面积，所以未改操纵参数。若以后实现基于实际舵面流体力，必须重新校准。

Deferred minor：尾窗仍是封闭窗面；顶部铁带一角按源码约越轮廓1cm、整图未见明显浮带；尾窗规整感、直檐边亮线和细索缩小后的点划影仍可继续打磨。当前不声称每个铁件逐点贴合或内舱已建成。

## 正式集成回执

perf-r6-c从实际公共主菜单进入自由试航，seed1661、1600×900、默认质量、三船35可见船员；10秒暖机后30秒412个样本，mean72.946ms（13.71FPS）、p50 72.268ms、p95 80.101ms、最差107.993ms，valid=true、invalidReasons=[]。仍远超16.67ms预算，不称性能通过。源代码在测量期间未变化，无其它Godot实例；本轮没有把孤立实验FPS当整场数值。

native-play-r6/00至08保存真实鼠标输入：普通主菜单进入单舰炮战、点击右舷齐射炮弹40→39并开始7.2秒装填；普通自由试航healthy船体/风帆100%，鼠标航向000→339度，三帆100→41→0%，停船0.0节；最终UI显示“继续”，现场已暂停。settings.sound/music回读均false。未注入状态或以受控序列冒充操船。本轮不重新认证键盘快捷键。

实际默认炮战在验收间隙迅速受到连续火力，从58%船体降至4%；这不是船模断裂或新的伤害参数改动，仍是值得改进的上手节奏。本轮没有认证战斗平衡或乐趣通过。

后续优先项：整场CPU/GPU帧预算、船/海/岛统一光照与色调、炮战初次体验。模型阶段保留上述非阻塞艺术细节；不再靠无关装饰数量代表质量。
