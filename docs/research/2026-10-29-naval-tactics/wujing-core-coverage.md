## 1. 版本、证据和采用规则

### 1.1 固定卷号，避免不同目录混用

本轮以维基文库 **《武经总要（四库全书本）》** 的卷号作定位键，以识典古籍的相应正文补充核读。四库本提要和御序将全书概括为：前集制度十五卷、边防五卷；后集故事十五卷、占候五卷。前集十六、十八分上下；该电子目录还将后集十九的阳局单列为“十九上”，阴局页题为“十九”。因此电子页面数多于四十，不能把页面数当成新增卷数。[四库本提要、御序及总目录](https://zh.wikisource.org/wiki/武經總要_(四庫全書本))

维基普通《武经总要》入口使用另一套页面编排，前集列到二十二、后集列到二十一；其中前集十九列西蕃，而四库本十九实际是益利、梓夔，四库本西蕃在十八下。**本文不拿普通入口的子目直接填四库本卷号。** 后续引用应同时保存版本、前后集、卷号、篇名；精确复原前再登记页码和影印版次。[普通入口目录](https://zh.wikisource.org/wiki/武經總要)、[四库本前集十八下](https://zh.wikisource.org/wiki/武經總要_(四庫全書本)/前集卷18下)、[四库本前集十九](https://zh.wikisource.org/wiki/武經總要_(四庫全書本)/前集卷19)

本轮查到中央研究院数位典藏的《武经总要》馆藏条目：著录宋曾公亮、丁度等编，明李鼎订、唐富春校，版本为明万历间刊本；这证明后续有可追索的版本资源，**不证明本轮已逐叶校过该刊本**。馆藏页面另列图像授权申请入口，未把馆藏图片下载入项目，也不把古书原文的公有领域状态等同于任意网站图像可直接用于游戏。[中研院馆藏著录与授权说明](https://ascdc.digitalarchives.tw/collection_8433983.html)

### 1.2 三层事实必须分开

| 层次 | 本文的含义 | 不可越过的边界 |
|---|---|---|
| 原文记载 | 本轮看到指定电子转录中的具体段落 | 不等于作者亲历，不等于现代实验验证，不等于已完成影印校勘 |
| 历史解释 | 由上下文判断器械、制度或战例的用途 | 跨时代同名船、兵器和官职不能自动视为同一规格 |
| 原创玩法 | 为舰队、港口、岛屿和经营拟定的玩家决策及反制 | 成本、概率、速度、视距、士气数值均待实验，不伪装成古籍数据 |

后文主题的 `正文已核` 只覆盖列出的段落。书中“船皆碎”“矢石不能败”“如飞”以及巨大载兵数、射程、听闻距离，只作文本记载，不产生无条件免疫、必杀或现代米制性能。宋书汇录早期事例也不使所有器物都成为“宋代同时在役装备”。

用户要求全书都进入核心元素的候选范围。本库据此保留技术、军政、后勤、地域、人物、礼俗等多种出现方式；“不直接采用”仅表示不照搬为现实规律或操作步骤。例如占候可进入人物信念与情报判断，但不让星位客观决定炮弹命中率。

## 4. 全书阅读与采用台账

### 4.1 状态定义

- **已读〔指定段落〕**：正文已打开并用于本文某个判断；不是整卷通读。表中写出范围。
- **仅目录**：已见本版本卷首子目／篇题或明确指出的首段，未逐篇核正文；只据此保留研究位置。
- **待核**：尚未闭合的缺字、异文、图版、地名、数量、史例互证或条目映射。它可以与“已读”并存。
- **不直接采用**：不照搬为游戏物理、现代科学或具体操作；仍可进入史料说明、人物、文化及背景。与阅读状态分列。

## 5. 持续扩充的最小记录单元

后续以一条器物、一段制度或一个完整故事为最小单位，不以“又读一卷”作为足够的录入标准。每条至少记录：

| 字段 | 应填写的内容 |
|---|---|
| `id` | 稳定来源 ID；同一条异文保留在同一记录下，不为不同游戏用途复制史实 |
| `edition / juan / section / locator` | 版本、前后集卷次、篇名、段落起句；取得影印后补册页与图号 |
| `source_url / accessed` | 直接来源及实际查阅日；转录、影印、馆藏著录分开标明 |
| `evidence` | 原文确实说了什么；转引谁、处于哪个时代、是否有缺字或仅目录 |
| `interpretation` | 可以合理理解的用途；不能推出的形制、性能和时代范围 |
| `game_roles` | 舰队／甲板／登岛／攻港／经营／人物／文化，可多选 |
| `decision / cost / counter` | 玩家改变什么、付出什么、对方如何应对；均标原创 |
| `reading_status / adoption_status` | 已读指定段落、仅目录、待核；核心候选、条件采用、不直接采用某类因果 |
| `next_check` | 下一次最小核查任务；不写笼统的“再研究” |

本轮台账是一张核查地图。下一轮优先顺序：

1. **补闭与海战最直接的原件**：前十一战船、渡具图；前十二港防可适配器械；前十三弓弩与遮护图。核图名、文本接续、单位和至少一种影印版本，不从缺图网页猜外观。
2. **补闭后集十四完整水事**：逐事录入水战、济水、断船路；对照相应正史、地理，保留记载冲突。史例效能不自动变成物理参数。
3. **扩展经营和人物**：前一选将选能、前三抽队、后八信任合作、后十五屯田与让功。让书的内容改变人、物和任务的关系。
4. **扩展边防网络**：先取前二十荆湖与广南、前十九川峡的具体水路节点，再核古今地名、海岸变化和里程。没有节点证据前不画精确路线。
5. **独立处理占候**：保存其原书份量与历史观念；剧情用语需读具体段落，客观天气与导航规则另建证据链。术数不是被删掉，而是以恰当形式出现。

## 6. 进入实验室前的候选课题

下列仅是由内容库导出的研究候选，**未登记、未实现、未运行**；若已有同类课题，应更新既有论文与实验而非另起重复 Demo。正式采用遵守仓库 [研究流程](../README.md) 和 [课题模板](../TOPIC_TEMPLATE.md)。

| 候选问题 | 来源主题 | 最小反例与接受方向 |
|---|---|---|
| 有时延的旗鼓／传令如何保持玩家控制感？ | C03、C08、C10、C13 | 一艘传令艇退出后分队仍执行明确预案；相同命令、时钟与可见性必须复现同样结果，UI 显示实际接令状态。 |
| 护送与过隘能否形成多种有效队形？ | C12、C15、C23 | 快船不能无条件穿过己方慢船；堵塞、撤回、预备队绕行均有可解释结果，不能以删去碰撞证明顺畅。 |
| 同一船的战斗、操船与修护人力如何竞争？ | C01、C04、C06、C17、C22 | 把所有人派去灭火后，不应仍保留满额射击和操船能力；也不能因单一操作进入永久失控。 |
| 攻港围困与补给是否产生可逆选择？ | C14、C16、C19、C21、C24 | 攻守双方都能换路线、求援、撤走；未知库存要显示不确定性，不能让 AI 读取玩家看不到的真实仓数而宣称公平。 |
| 线索与传闻能否既有价值又能被核实？ | C07、C11、C25、S01、S05 | 假线索不是不可识别的掷骰惩罚；玩家花费合理资源后能降低不确定性，文化解释与已观测事实分开呈现。 |

研究接受项必须分别包含状态正确性、真实 GPU 连续画面、必要性能成本和正式入口回归。本文完成的是可追溯的内容准备，尚未证明任何候选“好玩”“可平衡”“已接入”或达到完整游戏性能目标。
