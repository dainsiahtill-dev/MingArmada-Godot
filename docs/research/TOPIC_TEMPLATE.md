# 课题标题

- 课题 ID：填写唯一稳定 ID，与 catalog 一致。
- 报告版本/日期/负责人：填写真实值；改算法另记版本。
- 类型：前瞻工程研究 / 历史集成事后整理。
- 状态：提议 / 研究中 / 独立验证 / 待集成 / 已集成 / 搁置；填写理由和对应回执。
- 摘要：一句问题、方法和当前结论；未运行写“未运行”。
- Demo：填写已 allowlist 的本地资源；未实现写“无”，不能填假入口。
- 源码/数据/许可：填写仓库相对链接、版本与 SHA256；外部资料只作可选 provenance。
- 证据目录：填写 run-id；记录 planned / historical / measured，不能混用。

## 问题与假设

描述真实触发条件、当前表现及其影响；注明 scope。给出可证伪 H1/H2 和最小反例。

列单位、坐标 basis、输入域、接受时钟与状态所有者。未知值写 unknown，说明会限制哪项结论；区分物理规则、表现适配和源等价范围。

## 方案比较

比较至少两个合理方案的正确性、运行成本、状态/lifecycle 复杂度、场景适配和验证难度；说明采用理由。

记录已失败方案与可定位原因，引用原始反例；不能因为结果不合意删除失败记录。

## 算法与实现

写数学定义、数据结构、不变量、数值/退化边界、复杂度与状态转移。给简短标明性质的伪代码，再指向实际生产 seam 和独立 Demo。

说明随机数、cache、重复时间、暂停、回退/epoch、资源配置/释放的行为。声明哪些改动是目标适配，哪些仅有有限 oracle 等价。

## 实验设计

先定义基线与候选，只改变声明因子。固定 seed/初态、时间步/命令序列、地形、船型/数量、相机 transform/projection/FOV/裁面、viewport、quality、资源散列。

记录引擎版本、CPU/GPU/driver/backend、电源策略、暖机/样本数及重复次数。给实际操作或可执行 RTK 命令，输出使用新目录；不得依赖浏览器、服务器或外部 C 盘目录。

分别列 CPU 合同、真实 GPU、性能与正式入口的接受标准和失败条件。量化误差阈值、p50/p95 方法、排除规则预先写定；没有随机输入也要写 seed 不适用。

## 结果与证据

每条结论链接对应 run manifest、raw log、snapshot、原帧或数据。记录退出码、唯一成功标记、Godot ERROR、断言/失败数；原帧绑定接受时间和镜头。

区分计划、历史读到的结果和本候选新测结果；没有执行写“未运行”。性能报告范围、样本数、均值、p50/p95 及原始数据，不把微基准提升写成整场 FPS。

逐项对照接受标准写通过/失败/未测和证据位置。实际 GPU 观感需要审阅原帧，headless 合同不能代替；诊断隐藏物体或压力姿态单独标记。

## 局限与失败

列未覆盖输入、误差、性能边界、来源/许可限制和失败机制。写清哪些原算法/未知 ABI/像素/生命周期尚未闭合；不要用含糊“应该没问题”。

保留反例与无效证据纠错；说明下一次最小实验。范围之外不要作完成宣称。

## 集成与复现

给下一位 Agent 精确步骤：取同一源码/fixture，校验散列，配置工具，重放固定输入，审阅回执/原帧，检查接受标准，再过集成门槛。

列正式可达入口、packet/consumer seam、重建/暂停/回退/恢复/释放回归、存档与设置边界、导出资源验证。独立与接线均有新证据后，才更新 integrated。

给回退 seam、基线保留路径和资源恢复步骤；新 run 使用新目录，不覆盖历史失败。若只事后整理，注明不补造“先研究后集成”的历史。
