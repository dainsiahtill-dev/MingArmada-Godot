# Shore state submission subexperiment

ID: `shore-state-submission-2026-10-21`, under the existing `shore-surf` research topic and architecture convergence work. Status: measured investigation; palette candidate deferred before implementation. GPU and full-game performance unmeasured by this subexperiment.

Problem: each accepted source time samples all real shoreline patches and submits three material parameters per patch. Surface synchronization additionally broadcasts the same ocean time. Hypotheses: H1 these native API calls contribute measurable CPU work; H2 a scene-owned RGBAF parameter table can carry the exact float32 uniform bytes with one update per island, without moving controllers/RNG to the GPU. A separate scene-owned one-texel clock preserves independently accepted ocean time. No global shader clock, source frequency/population/quality reduction or new manager is permitted.

Baseline is the frozen source under `evidence/architecture-convergence-2026-10-21/baseline/source`. Compare full submission, omitted-submission diagnostic and candidate with identical actual terrain/patches/mesh arrays, seed, absolute times, controller states and opacity. Omitted submission is a diagnostic only, never an accepted renderer. The current 1704-patch fleet-world count must be verified by the harness, not assumed.

Acceptance: complete CPU native states and packet/mesh hashes match baseline; staged matrix/alpha/metres/time bytes equal the baseline shader float32 values, including cycle boundaries, rewind, same-time refresh, invalid time and source-opacity edits. Distinct scene owners never share mutable textures; disposal/reconfigure clears ownership. Unsupported RGBAF sampling/update or size limits must use the old uniform backend with a reason. Both backends remain switchable in the existing shore experiment. No per-patch legacy setters may remain in the table update loop merely to satisfy tests.

Performance: fixed actual formal terrain, 8 warmups and 32 alternating accepted-time pairs, nearest-rank p50/p95. Counter deltas identify sampler calls, material writes, texture publications and bytes. CPU timing is isolated shore submission, not world frame time, GPU completion or FPS. Preserve every failed result. Candidate remains off by default until actual GPU near/edge/wide, palette/alpha, mirror/occlusion and scene lifecycle evidence is accepted by the integration owner.

Primary APIs: [Godot shader interpolation and texelFetch](https://docs.godotengine.org/en/4.6/tutorials/shaders/shader_reference/shading_language.html), [ImageTexture update](https://docs.godotengine.org/en/stable/classes/class_imagetexture.html), [RenderingDevice format capability](https://docs.godotengine.org/en/stable/classes/class_renderingdevice.html#class-renderingdevice-method-texture-is-format-supported-for-usage). GPU table values are data, with no source-color conversion, interpolation, mips or wrap.

## Measured decision and narrower compiler candidate

`shore/baseline-01.json` verifies 1704 patches and 5112 dynamic writes, but full submission mean 13.602 ms versus omitted-submission diagnostic 13.529 ms gives no material measured CPU benefit. No table/shader/opacity changes are implemented. Counts alone do not identify a performance cause.

The direct live-world probe (`tools/profile-world-live-components.gd`) instruments configured production objects and preserves all script properties. It executes the actual current `World.apply_snapshot`, including the reflection camera, rather than reimplementing its sequence. `shore/world-detail-02.json`: p50 world 32.479 ms, shore sampling/submission 14.287 ms, surface synchronization 1.410 ms, atmosphere 13.628 ms, ocean projection 1.546 ms. Nested timers must not be summed. Cloud lifecycle itself costs 0.025 ms; changing its algorithm cannot address this hot path. Same-time refresh performs no curve compilation or shore shader writes.

`shore/world-compiler-detail-01.json` identifies 438 curve samples (312 scalar and 126 vector), 369 clocks and 49 UV matrices on each measured new presentation time. Static sky recomputation additionally performs 161 minimum-Z scans on 16/32 frames. Inner timing adds observer overhead; it identifies call distribution only. Existing transform kernels and static billboard-relative compilation are already accepted and remain unchanged.

Before implementation, H3: snapshot immutable source curve keys once when each private controller is compiled. Preserve raw double times for endpoint/search/vector arithmetic, source binary32 times/values/tangents for scalar interpolation, vector doubles and every source store/order. Keep the original mutable controller clocks and every per-frame sampling call, endpoint array ownership, complete render-state dictionaries, sampling frequency and source population. Do not cache world-cloud lifecycle, camera bounds, clock outputs or final poses. Do not add a process-global cache or manager. The untouched native oracle and frozen compiler remain available.

Alternatives: a shared shader table is deferred for lack of measured CPU gain; approximate curve coefficients, a lower sampling rate, scalar/vector formula simplification and static transform reassociation are rejected because source store order or accepted-time behavior can change. A per-controller compiled curve has finite instance ownership and is discarded with its compiled graph. Retained raw source dictionaries are immutable inputs to the compiled path, as already required by the compiler boundary.

H3 acceptance: red work counter through the actual render path; byte-identical complete states and controller snapshots against the frozen compiler for all atmosphere/weather assets, KF-bound storm sequence, camera bases, nontrivial outer transforms, include-vertices/minimum modes, repeated time/rewind and persistent clock history. Compiling/sampling cannot mutate input assets or earlier published states. Alternate baseline/candidate order for 8 warmups plus 32 measured 9-instance batches (six fog and three world-weather instances), record hashes, p50/p95 and raw samples. Retain production changes only if the headless CPU reduction is repeatable; GPU visual acceptance remains owned by the integration task and cannot be inferred from CPU evidence.

Result: H3 retained for parent integration acceptance. Final frozen receipt `shore/cloud-curve-green-03.json` has 3228 assertions/0 failures, source parser work 438→0 per nine-instance batch, complete states/clocks byte-identical. Three alternating A/B runs improve compiler p50 by 13.8%, 14.7% and 15.6%; final mean improves 16.4%. Sixteen focused scripts pass. Independent review corrected absent-key alpha null compatibility and added a helper SHA256 to the final receipt. No production changes beyond the compiler plus its private curve sampler. Separate live-world timing does not prove a whole-game FPS improvement; parent serial GPU/whole-game acceptance remains required. Full provenance, hashes and limitations are in `shore/README.md`.
