# 正式航行、表现收尾与首航体验

用户已批准上一轮四项路线并要求全量落地。本轮目标是可从正式入口连续游玩的航行/战斗/返港链路，而非重复学习台。当前工作基线42761b71e73c1174eecf5a34e524d80475c06df3，启动时工作区干净。

## 范围与边界

1. 正式自由试航：真实入口、海面鼠标目标、顺逆风前进、反打/减速、右键环绕、滚轮、连续炮击、岸边和返回主菜单。普通操作不能被物理逆风锁死。记录完整帧间隔及接受时间，不拿实验室FPS替代。
2. 已知表现缺陷：低位投影裁切/大面片、远景浅滩矩形/大色块、船上方异常细线。先复现并区分本来可见的桅索/投影与真实异常，再修改；保留最新羽化width0.6/weight0.55、原五波、尾迹、3D甲板人物。
3. 操作反馈：复用原 mouse_course、casual/manual assist、camera controller 与炮击状态机。避免重复接受输入或在物理补步中重复全套呈现。船首/船侧水沫要在已有 hull-contact 课题验证上下浮动、转向、停船与重入水；尾部不改。
4. 首航：先审计已存在 opening_story、第二委托/aftermath 和UI，复用实际接单/航行/战斗/交差/升级/安全保存Continue。收敛目标提示、剩余时间、决策后果与下一航次入口。目标10–15分钟是待实机测量的节奏目标，不能伪造时间、传送或注入交易完成。
5. 所有新算法先在既有实验室课题做独立对照与论文；必要新课题有唯一id及统一入口，不添加无关顶层示例。天气和炮火已有实现优先验证，缺口经明确反例补齐，不无条件重写。

## 交付与验收

- 每个失败有baseline、单因素假设、正确调用链RED、修后合同与实际场景证据；失败材料保留。
- 正式试航实际帧测量声明相同quality/MSAA/分辨率/船员数/原画面负载。目标60FPS/p95约16.67ms作为目标，未达到必须报告实测而非降低标准或删演员。
- 画面近/中/低三镜头和连续0/.5/2/8秒；修复不覆盖旧岸浪/羽化/船尾接受记录。
- 玩法至少完成一条真实首航并验证分支后果、一次收益/升级、安全存档与普通Continue；对应UI能说明当前目标和下一步。
- 受影响测试、重新检查上轮8异常的当前状态、最终独立审查与PCK资源验证。已有8项不能未经复验称已修。
- 测量过程独立用户存档，保留编辑器及用户运行实例。禁止伪造原游戏动态观察和正常原生输入；自动脚本与Computer Use证据区分。
