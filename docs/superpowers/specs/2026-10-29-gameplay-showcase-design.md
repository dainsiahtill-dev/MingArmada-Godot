# 海上明旗 · 玩法长卷网页

用户要求：制作持续介绍各种玩法的前端网页，加入项目已经生成的素材、模型渲染与真实截图；每次项目出现新进展都同步网页。沿用既定青绿海疆原画、墨青、旧金和朱砂；装饰克制，明确画面来源和玩法实现状态。

## 选择与范围

- 采用项目内独立静态站 `web/gameplay-journal/`。无运行时依赖、无账号、无外部字体；可通过 HTTP 或直接打开构建后的 HTML 阅读。选择理由是游戏为 Godot 工程、没有现成前端框架，且此处需要长期内容展示而非后台应用。
- 备选为 React/Vite：方便复杂应用交互，但此站只有内容筛选、图鉴和图集，新增依赖无必要。用户后续要求局域网/外网访问，随后明确选择自行配置frp；最终采用监听0.0.0.0:4173的独立静态服务。此前曾创建owner-private Sites草稿并在游戏仓库外准备网页白名单源码包，未部署；按最新选择保留草稿而不继续发布。
- 用户此前已委托自主推进并明确视觉方向。本次按其方向作常规实现选择，记录设计与计划，不重新发起批准流程。
- 不修改正式游戏算法、运行入口、用户存档；保留现有 dirty 工作。

## 阅读体验

访客先在青绿海疆原画中进入世界，再读清楚当前能玩的火攻、可见货物和粮食贸易；之后探索船型、职业和生涯设计，最后看到真实图集与持续更新的开发航志。

1. **首屏**：既有无字生成原画大幅展示，中文书法/宋体标题、简短介绍和两个真实锚点入口。图注明确“生成原画”。
2. **玩法长卷**：按“全部／已可玩／实验中／规划中”筛选，支持中文搜索；选择一项显示真实图片、玩家决策、代价和状态边界。空结果有清空筛选入口。
3. **舰船图鉴**：按用户追加名单扩充至25种职责原型，五类战术筛选；每型有优势、制约、打法、配员、反制。福船使用真实 Blender 渲染，其余明确为设计方案；不能让复用同一福船图片冒充不同船型。
4. **海上生涯与父子主线**：地图/插画配章节，说明贸易、护航、劫掠、守港、征讨的设计递进；双主角新主线尚未可玩。
5. **实机与制作图集**：大图加异尺寸辅图，标注“正式游戏／独立实验／模型渲染／生成原画”，可打开原图、前后切换、Esc关闭；保持键盘焦点和返回位置。
6. **开发航志**：按真实进展记录更新，展示日期、状态、具体变化和下一步。用户不必从测试数量猜完成度。

## 视觉合同

- 场景：项目所有者在桌面浏览一幅航海绘卷，既欣赏画面，也核对当前玩法，阅读应安静、清晰。
- 保留游戏已承诺的墨青、旧金、朱砂、暖纸原画；深墨青为正文基底，纸色限原画和海图区域。
- 标题系统宋体/楷体，正文 Microsoft YaHei/PingFang 等中文无衬线。字号有层级；正文不小于16px，中文行宽受控。
- 金边用于分区与选择，云纹来自原画，不另堆CSS装饰；避免重复大圆角卡片。弹层有克制投影。
- 状态有中文文字，不能只靠色彩。支持 focus-visible、触控、reduced-motion、320px至宽桌面。
- 使用项目已有资产并保留完整原件，不生成假的实机图片；地图底纹不冒充准确地理。

## 内容与持续同步

`content/gameplay.json` 是玩法/船型/章节/更新日志源，`content/media.json` 是图片原路径、来源类型、说明和出处的白名单。构建脚本校验结构、来源路径、图片存在、关联ID并复制白名单资源，输出完整可独立打开的 `dist/`。

每次有新玩法、算法验收、美术资源、正式集成或已知缺陷变化，同一批工作必须更新相关内容、更新日志和必要图片，再运行构建与 `--check`。新测试通过不自动把“规划中”升级为“已可玩”；需要正式入口证据。规则写入根 AGENTS.md 与站点 README。

## 接受标准

- 有实际可打开的网页，真实内容和图片齐备，所有导航与交互有效。
- 筛选、中文搜索、空态、图鉴切换、图集键盘关闭/焦点返回、手机菜单、开发航志均实际操作。
- 浏览器检查桌面、平板、手机/窄屏，无水平溢出、缺图或不可点击内容。
- 来源和状态与28、31号交付记录及当前实验相符；529项工时核心通过不能写成生涯接线完成。
- 构建可重复，`--check` 能发现未同步输出；无外链图片、网络字体和凭证。
- 局域网服务仅提供dist，GET/HEAD、禁止目录浏览与越界；自定义Host/转发头可用。用户自行配置frp，真实外网域名待其配置后验证。
