# 第二航次最小可玩升级：这一趟赚来的钱，先给谁

状态：**设计规格；新增对白、分红结算、意向收据与结账目标均未实现、未运行验收。**
日期：2026-10-12。仅编辑本文件；不改产品代码、QA证据、Git或水面/岛屿/特效。

## 目的与范围

承接1650年原创虚构年轻船长、厦门旧账册和400两父辈欠款。第二趟运20粮至近岸补给点，让玩家把一次真实收益变成自己的决定：回家清债、照顾随航船员，或保留下一次出航的本钱。通过真正航行、扣银、治伤和偿债兑现，人物记住的是已发生的行动。

本轮只推荐**一场能闭环的交差后去向决定**，含三个可比较选项。前置承诺和真实遇敌战术列为后续条件节点，不为凑两个节点制造风险。成功首航无伤员、敌舰已沉的平静第二趟同样可玩。失败局沿用真实损失，不能用一次谈话换回人、粮或船。

读者同时参照 [原第二航次设计](next-voyage-story-design.md)。该稿的三拍方向保留；本规格收窄最小交付，并修正“医疗与威胁都不存在时，剧情节点全部略过”的缺口。它不是新的完整工程实施计划。

- `kinmen-supply-deep` 是目前唯一金门至补给点合同路线，不伪装存在新的近路。期限从承接起1200模拟秒；本规格不暂停、延长或重置期限。

- `treat-wounded` 真实每人4两、30模拟秒，开始作业先付钱，完成才把伤员变为健员；死亡不会恢复。各船作业并行时不能把时长错误相加成全队等待时间。

- `repay-debt` 需真正到厦门、旗舰原生安全锚定；扣实际银、减实际本金。部分偿还没有信用奖励，结清本金沿现有规则一次加6商人信用。
- 存档V2对场景、命令、回执和债务连续性有严格校验；新增规格不能只往JSON塞字段后宣称兼容。

本次只读已有 `native-return-complete/normal-ui-save-v2.json`：第二委托已装载、仍在金门，库存30粮、银915两、模拟时刻1524.2、期限2724.2。这是旧文件的事实，不证明本轮第二趟已真实航行/交差。此成功局银足以清债，不能编造“只有几个铜钱”“不分红船员马上叛变”等虚假稀缺或惩罚。

不采用“旗舰顺带买5粮”作为核心节点：该快照金门现价买5粮70两，成功交20粮后补给点卖5粮仅61两，正常成功分支是被支配的交易。不能捏造溢价、采购商或敌舰来使它显得刺激。旗舰载货吃水系数目前为0，也不能声称这5粮必然增加吃水。

## 玩家先看到什么

触发须同时满足：`convoy-002` 有合法正式claim，状态为 `settled` 或 `failed`；旗舰实际在补给点安全锚泊；未记录本场决定。若真实交差发生在海上，只提示“已结算，安全靠补给点后核账”，不声称已与岸上账房见面。

显示一张短账单：装20、实交、实损、基础报酬、奖金及其真实资格、当前银两、未偿本金；逐船列当前健员/最低人数/伤员和船损。本航新增死亡单独列，首航已有死者不得混入；当前伤员可以来自旧航，不冒称全部是本航新增。

本航死亡按实际承运/实际参与护卫船、装载至claim之间的可追溯伤亡事件去重。第二装载回执的 `ships` 当前只含粮船，不能直接当全队死伤账；旗舰、快船需引用真实护卫参与和 `near-casualties` / `crew-transition` 来源，转移人员不能当死亡。若缺完整来源，列“承运船已核实死亡N；护卫船人员明细待核”，禁猜总数、禁收抚恤费。

台词最多两句，数值从账单投影：

> 账单：这趟实交{delivered}粮，实收{reward}两，旧债还剩{principal}两。
> 许福：旧账可以往前翻一页，弟兄和下一趟船也得有个安排。钱先用在哪里，由你定。

许福只作为既有原创关系人物，不编造成某条真实死亡事件中的具名船员。船上管事发言必须有真实存活及所在船记录；没有合格发言者用账单，不借对白复活林/陈管事。无伤亡明确说“本航未核实新增伤亡”，不强演悲情。

## 一场决定，三个实际去向

### 选择一：回厦门，把旧账还掉

按钮：“回厦门偿债”。显示建议金额 `Q=min(当前银, 当前本金)`，允许玩家改为正整数且不超过该上限；本金已0或银为0时说明真实原因。

选定只记录可改变的去向意向与拟还Q。**补给点不扣银、不减本金、不加信用。** 目标变为“完成本港必要港务，驶回厦门安全锚定，偿还Q两”。旗舰仍需真实出航、海图选点/操帆和靠港；不制造反向合同路线，不瞬移全队，不把地图上点击厦门写成到家。

到厦门后再次读真实银、本金和原生锚泊门禁，报价有效才提交已有 `repay-debt`。若途中买卖/修船后钱少了，显示新可还额，玩家确认新Q；不自动透支，不把旧计划自动算已兑现。可改主意、暂缓或切换目标，无额外罚款和催促倒计时。

完成反馈：“实际还{amount}两，旧债{before}变为{after}两；船上还剩{silver}两。”关系文案：“林家商行收到实际偿债”，引用真正偿债回执；结清时沿已有信用+6。父辈债务的数字变化和实际返航构成故事回报。

代价：往返航行和投入本金占用资金；途中仍承担原生船况和人员风险。留银者保留流动资金，不能说还债永远最优。915两成功局可清债并留本，界面必须诚实呈现这种宽裕局面。

### 选择二：这趟收益，先分给随航弟兄

按钮：“按实收报酬分两成”。**新增、未实现的最小财务规则**：`R=claim.details.baseReward+claim.details.bonus`，`P=floor(R/5)`。R必须来自合法第二claim，不从库存粮、合同标题或按钮次数推算。

全交按时R=250则P=50；迟到全交R=200则P=40；交15且无奖金R=150则P=30；R=0则不提供分红按钮。若P=0、当前银不足P、无真实存活随航船员，显示原因，不凭领取按钮增银或给死人分钱。旧账册80两工钱支付不影响本规则，也不得被当成已分第二航收益；这是来自第二实际收益、绑定第二claim和单次独立收据的新支出。

实际收款对象限定真实参与本次的船组、真实仍存活的健员/伤员；不把俘虏、背景商船或已沉船船员算进来。按合格船ID和各船实际健员+伤员数量记录总受益人数；不凭空添具名人物。第二航收益分红转出船长银两给这群现有船员，只借用现有工钱等支出的原子扣银/回执模式；旧欠薪回执不充当分红或claim证明，也不宣称已模拟其个人消费或完整薪酬系统。

提交新的一次性分红事务，在安全港实时重验claim、船员、revision和银两；真正扣P银，生成绑定claim的独立分红收据。**本最小版本不额外增加抽象声望、不治伤、不补员，不给即时战斗增益或战斗胜率奖励。** 关系页只记“本航已实际分红P两”；现有旧账工钱+10和独立首航交差分红+8规则各自保留，不能互换或搬给第二航。更广的未来承诺、人情反应与长期选择效果尚未实现；若未来要给第二分红数值声望，需另作平衡/存档规格。

若当前有真实伤员，旁边显示已有逐船治疗报价，“先治{q}人：{4q}两，{30q}模拟秒”；这个入口调用现有港务，玩家可在分红前后自行排序。低员船要治到最低或保持停航；无足够伤员补足缺口时明确无法治疗解决。无伤员就不出现治疗按钮，不制造医疗费，也不以零人作业刷完成。

作业完成才显示“{ship}实际治愈q人”；分红后若银不够治疗，真实报价拒绝，提醒差额。玩家可选择先治伤再重新考虑分红。不得把两笔事务合成无明细的“善待船员套餐”，不得一次扣两遍。

代价：P是真金白银，不能再拿同一笔钱偿债或修船；治伤同时占用真实资金和港内作业时间。得到的是已兑现的分红与具体可用健员，失去的是流动资金。没有伤亡时，分红仍是可执行的关系和财务选择。

### 选择三：留下本钱，先看下一趟需要什么

按钮：“留作船本”。记录意向，不扣银、不送声望、不清债。列当前真实可报价的修理、治疗、买卖入口及承家号的实际状态；可预览以后在厦门申请的已有修理/帆装改造，不能在补给点提前执行厦门专属服务。

反馈：“报酬已入账；未偿本金仍{principal}两，银仍{silver}两。下一笔支出由你决定。”不宣称已投资新船、不自动开放第三委托、不赠新船或新角色。当前无招募补员来源，死亡造成的缺员不能靠“投资人员”文案解决。

代价：旧债、旧伤和损伤继续存在；保留资金让玩家以后真实支付修理、治疗、贸易或偿债。没有额外失败惩罚，不能制造“限时错过下一船”来逼支出。

## 可选前置与海上节点：本最小交付不要求实施

1. **出发前的口头承诺**：有真实W伤员才比较全治/补最低/留银；用现有逐船治伤和完成收据兑现。W=0直接略过。可以说“这次获利再分红/回家还债”，但只展示待办意向，未付不奖励好感，不强制扣未来收益，不冻结医疗资金。跳过承诺也能正常进交差后决定。
2. **保护还是追击**：仅活动第二委托真实underway、实际观测到存活合法敌方目标时出现。护送用现有 `assign-order` 的 `protect`，追击/压制用 `intercept` / `focus` 及真实炮击；原生权限、目标、弹药、低员、作业门禁仍在。敌舰已沉、被俘或不可观测就不出现，不复活补敌。手动覆盖命令自由；只记成功受理的命令与实际事件，不点击即胜利。本段不直接改声望，交差账只读实际货损/伤亡。

不新增医学用品、随机伤病、海盗定时刷新、战利品奖励或返航采购特价来凑选择。若最终只有一场决定，也按这一场实际闭环验收。

## 收据、保存与状态边界

设计中的新场景ID建议 `second-return`，仅在新模块/扩展投影中新增；原三场七选择、旧收据和旧存档解释不回放、不改写。

去向决定收据键：`{campaignId}:convoy-002:aftermath-plan`。分红收据键：`{campaignId}:convoy-002:crew-dividend`。两者类别及details必须明确加入现有V2校验；不增加任意宽松字段。

计划details固定记 `contractId`、合法 `claimId`、`choiceId`、`portId`、`plannedRepayment`（只有偿债意向为正整数，其他为0），零直接经济/声望影响。去向可改变时追加有唯一commandId的改计划回执并指向原计划，不覆盖历史；限制/缓冲沿现有回执上限。最小实现允许普通港务独立于计划继续使用，剧情不封锁任何合法交易。

分红details记合法claimId、R、P、源claim报酬字段、参与船和受益健员/伤员数量、银前后、声望前后（本版本完全相等）。只有成功新事务产生这条记录；重复commandId返回同一结果，新的commandId重复分红也被固定键拒绝。没有本航报酬或受益船员时不会生成“零成本完成”。

计划兑现由真实回执投影：偿债引用发生在计划之后、厦门真实合法的 `repay-debt`；分红引用新独立分红回执；治疗引用各自 `work-completed`。部分偿债实际少于Q只标“部分兑现”，不因计划总额显示结清。留本只标“已决定留本”，不伪造作业完成。

旧存档无新回执默认未作决定；旧首航和真实第二装载仍合法。海上save仍按当前安全守卫拒绝，不能为故事放宽。安全港普通存档、Continue及导入后，意向、银、债、分红和完成作业必须读回一致。

## 失败与变体

- 迟到或货损：R按实际claim变小，P随之变小；没有完整奖金，不可把50两预算强套到部分交付。
- 交0：账单写失败和真实货损；分红不可用。若仍有旧银，可合法治疗、返厦偿债或留本，台词不称“这趟赚了钱”。
- 旧伤仍在：医疗显示真实当前W，完成来源单列；不把首航伤员变成本航新伤。
- 部分沉船/死亡：保留真实船损、死亡和存活人数。分红不能给没有受益人的船；新抚恤8两/人及死者家庭系统属于旧稿后续设计，本次不实施、不开收费按钮。
- 全队毁损：无实际安全港就不触发岸上结账；展现损失事实，玩家可手动读已有合法checkpoint或新开局。不自动复原。
- 承接后未出航就选择结账：无第二claim，拒绝；计划不能把20粮库存或预计250两当收入。
- 钱不足、报价过期或原生投影失败：拒绝该实际支出并保留原状态，计划仍可待办；不写成功关系文字。
