# 船员作业独立实验实施计划

> 使用 writing-plans / executing-plans / test-driven-development。已有用户自主推进授权；共享工作区含必要但未提交的资源，保留原处、限定新增课题，不建立丢失这些资源的干净分支，不提交。

## 目标与边界

为父子双主角 CH-01—04 共用的船上生活提供第一块可运行机制：同一批船员在炊事、鼓乐、修船、炮位、休息之间分配；人员调动同时改变生产与战备。新实验不读取、写入正式生涯或用户存档。36 职业、英雄、代际传承仍待后续实现。

## 合同

- `game/research/demos/crew_role_rules.gd`：纯 RefCounted，`configure({preset, specialists}) -> {ok,error?}` 原子重置；`assign(worker_id, role) -> {ok,error?}` 原子调岗；`step()` 恰好推进 1/32 秒；`snapshot()` 深拷贝。角色为 cook/musician/carpenter/gunner/rest；12 个稳定人员 ID `crew01`—`crew12`，一人一岗。
- `snapshot`：tick,time,workers（id/name/specialty/role/fatigue）,grain,cooked_rations,wood,hull,sea_repair_cap,morale,gun_efficiency,ledger（grain_used,meals_cooked,meals_eaten,wood_used,hull_repaired）,counts,rates,options。无随机。
- `balanced`：粮24份、木16单位、船体54/100、海修上限80、士气40/100、疲劳60/100；前3人依次厨/乐/修，第4—7人炮位，余5人休息。`scarce`：仅粮0.5/木1；`emergency`：第4、5炮手改修船。原计划粮12/木12无法独立触发容量上限，复审后扩大库存并加入剩余资源不再被扣的回归；保留原失败回执。
- 专业人员本职效率1.5，普通水手1；炊事有效工时上限2、乐师上限1.5；基础炊事每工时秒0.5份（粮1换熟食1），修船每工时秒0.75船体点（木0.5/点），无库存则停止。熟食最多12份。修船初版有效工时上限2，经84案扫描暴露第二名支援无产出，默认候选改为三个实际工作位；按效率及稳定ID选人，保留legacy_cap重放。所有试验系数尚未获全局平衡验收。
- 休息每秒减疲劳0.2；每秒最多给一名疲劳未满恢复的休息者一份熟食，轮转公平分配，减疲劳6；鼓乐每有效工时秒恢复0.7士气×休息人数/12；炮位效率=min(有效炮手数/4,1)。数值均为待调游戏参数，无历史真实性宣称。
- `crew_role_experiment.gd`：Node3D，宿主独占时钟，固定步、暂停/单步/重置/销毁，snapshot含fixed_step。参数 preset / specialists / repair_detachment；后者实时将crew04/05抽调修船或返炮位。深海色既有主题；局部滚动适应窄视口。无自建进程、存档、音效。
