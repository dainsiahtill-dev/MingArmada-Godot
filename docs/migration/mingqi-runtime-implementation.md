# 1650 原生运行时与组合场景检查点

2026-10-11。此检查点把现有 1650 纯领域、原生海战和原生 Control 接通；完整 Godot 迁移仍在执行。

## 权责和时间

`MingqiRuntime` 协调业务命令、暂停原因、近远场同步和保存资格。`NearFieldBridge` 以 battle epoch、tick、controls sequence 和单次消费约束交接；出售退役与释放俘获分别处理，不能把释放船误删。`SailingSimulation` 在原海战实际使用的 1/60 秒步长上处理输入、命令队列和插值。原独立航行实验的 120 Hz 不被套到现有 Encounter。

领域负责银两、货物、船员、合同、俘获及回执；海战负责船位、伤害、弹药与战术。UI 只显示快照、发送意图，`NativeReadiness` 从当前原生状态派生可执行提示，业务命令仍在执行点重新验证。场景、船模、水手和效果消费已接受的时间与事件，不以墙钟推进海面或经营。

## 操船与生命周期

保留来源的均衡/真实操船策略。按键、调帆、舵角和自动调帆进入同一个控制队列；同 tick 的部分字段意图从队列中该船最后一条合法控制合并，既不覆盖另一个字段，也不引入独立缓存。暂停清空待执行输入；导入创建新 Simulation。非法、未改变或其他船的控制不会解除当前旗舰导航。

按钮、下拉框和滑块的焦点不阻断操船；可编辑文本框占用键盘。菜单、窗口失焦、载入、错误和结果状态共同约束运行。面板布局在最小尺寸变化与视口变化后统一更新，关闭状态和当前选择在结构性快照更新后保留。

## 存档事务

`SaveCoordinator` 使用独立 `user://saves/mingqi-v2.json`，经过临时文件写入、flush、回读验证、旧文件 rollback、提交与备份轮换。导入先验证独立候选状态和原生保存安全性，再落盘，最后替换运行时；失败保留原运行时和原 bytes。继续默认暂停，不补算离线时间。备份失败有真实提示，不掩盖已有文件。

## 实际画面与边界

`game/scenes/mingqi/mingqi_scene.tscn` 组合真实五船、GLB 动画水手、海岛、明亮海面、原生经营与战术 UI。`--capture-mingqi` 接受实际护航合同、实际离港并推进五秒航行，然后记录固定岸线相机的连续原生 PNG。每张记录引擎、GPU、相机、viewport、业务/海战状态和水手诊断。PNG/JSON 写盘会干扰监测时间，不能换算稳定 GPU FPS。
