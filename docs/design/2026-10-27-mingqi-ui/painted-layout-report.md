# 明旗航程：绘制组件布局

本轮按用户最新要求改为深靛青漆木、旧金雕花、朱砂页签与奶油色文字；UI 使用独立生成 PNG 组件，文字和交互仍由 Godot 原生 Control 承担。这是静态排版与资产组装，没有新增表现、玩法或性能算法。

左上 `hud` 只保留船长、账目、航况、真实炮侧状态、目标与回执；默认宽度上限 370。`sailing_manual` 按钮移入下方操作轨，原四行说明 `keys` 仍在左上按需展开，保留既有手册状态与快照重建行为。HUD 内有原生滚动容器，小窗口不会把内容挤出视口。

下方 `command_dock` 先放六个页面页签，再放暂停、倍速、菜单、驾驶/海图视角、停船和手册；页签的选中态由真实页面状态更新。操作轨在宽窗口约 104–132 高，小窗口为 128 高并可滚动访问所有命令。每个控件仍使用原节点名和原命令合同。

右侧 `operation` 使用 folio 图像框。小于 960 宽时放到左上摘要下方，底部始终避开操作轨。页面内容继续使用原生滚动；操作行由原生 HFlowContainer 换行，避免窄窗口横向裁掉按钮、数值框或炮弹选择。320×480 为可滚动访问范围；并不把该尺寸宣称为适合连续操船的推荐窗口。

`header-cartouche.png` 位于 `assets/ui/ming_maritime/painted/`，载入前检查资源、载入后检查 Texture2D。缺少素材时实时标题仍可使用。装饰图与文字 `MOUSE_FILTER_IGNORE`；全屏空白区仍属于世界输入。generation、mount token、nonce、重复命令、编辑草稿、资格检查与实际剧情/贸易/航程数据路径保持原合同。

验证记录：`test_mingqi_painted_layout.gd` 初次真实运行先红，旧界面缺少独立操作轨，1 断言 / 1 失败；原始输出见 `painted-layout-red.json`。最终真实运行 `painted-layout-final.json` 为 81 断言 / 0 失败，覆盖 1600×900、1280×720、320×480、六页切换和选中态、小窗口逐个滚动到完整命令、六页横向可达、手册和重建。夹具无原生船舶时，宽窗口摘要实际 370×147，操作轨高 109；手册展开后摘要 370×234。1600/1280 两种宽窗口的中央无遮挡水平间隔分别 754/434 像素。真实航况和剧情会改变摘要内容与高度。

既有回归：`painted-ui-final.json` 195 断言 / 0 失败；`painted-manual-final.json` 0 失败；`painted-voyage-flow-final.json` 通过。`painted-file-dialog-final.json` 为 10 断言 / 1 失败：旧测试将奶油按钮文字与 `Parchment.PAPER` 白纸背景计算对比度，和本轮深色方向冲突；其余真实弹窗、纹理、中文、文件模式、过滤器与无命令语义通过。已将冲突交给主题/统一验收负责人，不改回产品颜色。

保留中间失败：第一次接入测试把倍速节点误写为 `speed_1` / `speed_8`，真实旧合同为 `speed_1_0` / `speed_8_0`，更正测试后通过。未缓存的 PNG 加载与三个并行进程曾触发 60 秒 runner 超时；主题负责人随后加入逐路径纹理缓存，最终新布局测试用时约 8 秒，manual 约 5 秒。旧 UI 195 项回归约 59 秒，仍接近该 runner 的 60 秒上限。没有将这些中间记录删除或冒称通过。

真实 GPU、原生全入口和完整游戏输入由本轮统一验收记录补充；本文件的无窗口布局测试不能证明素材画面、完整游戏输入或动态海况/FPS。
