# 港口、经营与家事 UI 细节审查

日期：2026-10-22。范围为 `prototype/render-life.js`、`prototype/life.css` 所拥有的28页。此轮为完整网页原型的细节完善，不宣称原生 Godot 玩法、真实航次或史料原件已经完成。

## 审查依据与主要缺陷

读取 PRODUCT.md、DESIGN.md、renderer-contract.md、systems.json 的页面描述与112项状态，沿用已核剧情及其历史／创作边界。目视检查旧版 market、letters、port-hub、accounts 全页预览，以及本轮采用的港口专用插图。

旧版主要问题：港口地点按钮压在运货人物近景上；市场没有把实际限额、货位与可用银放在验货旁；委托缺筛选与交验层；账房虽有流水但缺用途和凭据；家书匣没有草稿／未知送达的完整层次；关系与势力过多依靠普通段落；状态下拉缺少对应的页内条件。

## 公共交互与事实边界

- `state.previewScenario` 只用于本地派生视图、状态解释、筛选、时代节点与禁用原因。不会修改真实银两、库存、承接或寄件记录。
- 112项目录状态各有独立的条件说明、可支持的反馈与边界。需要真实记录的完成、交验、收到、已读等状态，若没有记录则显示空态或未落实原因，不代造成功。
- 货舱容量默认350；米粮／生丝／香料每单位占1位，木料／铁料／瓷器每单位占2位。通过 `ui.cargoUsed`、`ui.cargoWeights` 合同计算，初始使用194位。
- 港市库存、现银与加权余舱共同构成买单上限；普通港市与隐蔽锚地的库存来源分开。
- 承接按 `acceptedContracts`／`acceptedContract` 的实际ID判断。交验由 `deliver-contract` 登记 `pending`，不会凭提交自动给报酬。
- 信件通过 `sentLetterRecords` 完整回读。草稿、拟附银、收信人与托寄船分别显示；托寄不自动变为收到。
- 外交分别登记合货、接应、停手草案。没有对方回应模型时明确保留为拟议，不自动结盟、发银或打开通路。
- 通知使用真实 `notifications`，支持分类、未读／已读过滤与 `mark-notification`，已读不会自动结束事项。
- 不复制传世家书，不将情境插画当成历史现场或文书原物。无确切依据的年份、船数、兵力、伤亡、药量与水量均不补造。
