# 《一官入海》3D资产生产清单

日期：2026-10-22。对应[机器可读清单](production-assets.json)、[30玩法系统与11底层系统](systems.json)及唯一[43场剧本](../../narrative/zheng-zhilong-story.json)。

本清单给出六幕单人正式游戏的建议生产预算。当前用户目标仍是彻底完善72页可点击网页；网页可先采用合格插画、实物图、矢量示意及演示状态。不能因为未来原生游戏需要3D，就把全部3D制作当成网页验交前置，也不能把页面上的PNG或示例数值称为正式玩法完成。

## 确切预算

**完整建议83个独立基模；六幕单人必需部分81个，另2个为可选陈设。** 83不等于83个全部新建：51个计划新制、18个从现有文件提取／适配、14个保留程序式或复验后复用。后三类判定仍待美术、来源、运行与导出复核，没有本次已制作完成的含义。

| 船舶 | 8 | 5 | 3 | 0 | 24 |
| 人物身体与头部 | 16 | 2 | 14 | 0 | 48 |
| 独立服装与配件 | 8 | 2 | 6 | 0 | 24 |

- P0：47基模、129份LOD交付，组成接差、港口、配载、航行、海战、救援、交割与恢复的完整核心循环。人物可先使用共享外形，不代表六幕主要角色已经全部完成。
- P1：34基模、92份LOD交付，补主要人物年龄阶段、两岸家庭、跨文化遭遇、重炮敌舰与完整六幕内容。
- P2：棕榈与晾晒架2个基模、6份LOD交付，只是可选环境陈设；不增加多人、海怪或幻想舰级。
- 72个基模各交3档LOD，11个近距小物各交1档，共227份。P0＋P1合计221份，含P2为227份；这是目标交付表示／文件预算，不是现有GLB文件数量。
- 额外列出117个材质、同拓扑形变、装载或节点显隐配置标签。它们不构成117个新基模，也不把所有搭配排列相乘。
- 骨架2套：成人、儿童。动画去重29段：成人21段、儿童6段、刚体道具2段。头、服装与LOD共享动画，不重复统计。

“LOD交付份数”按每条基模的`lodLevels`求和。DCC资产可交独立GLB；保留程序式的资产可交等量原生Mesh资源与生成代码。该计数不假设所有程序式资产都必须先转GLB。实际项目采用自动LOD时，需要重新约定交付文件口径，不能把自动生成的多个实例再算一套基模。

因此，**当前磁盘是27个GLB，不能说已有27个独立生产基模**：18个是6船型的LOD，3个是同一水手的LOD，另外6个是许可与形制尚待处理的参照。

活动`game/presentation/ships/ship_view.gd`与`game/scenes/ship_book/ship_book.gd`均调用`modules/scene_engine/assets/ship_model_provider.gd`。provider读取`assets/data/fidelity_naval/ships-manifest.json`，把fuchuan映射barque、fisherman映射sloop1、merchant映射ship_merman、voc映射frigate、patrol映射ship_brigantine、heavy映射treasure_galleon。其`same_source_lowend`策略为3个独立节点复用同一lowend几何，不能据此称已有3份精度不同的参照LOD。

旧船文件的参数、名称和造型并不证明历史准确性。尤其heavy的旧参照名不能推导出本游戏必须生产“宝船”；预算只要求一类符合时代目标的重炮敌舰。原版参照的提取路径、转换工具和本地文件存在，也不自动解决发布许可。

## 资产粒度与复用原则

身体、头、外衣、帽具均独立计数。3个身体、13个独立头部共16项；8个可换服装／配件另列。主要人物不只是把同一头像换色；普通短场人物可在共享头拓扑上做有限形变。若后续形体变化需要新拓扑，应新增基模并重算。

建筑采用12个有限模块，不按整港或整栋建筑数量乘算。货栈门面、墙、屋顶、门窗分别列出，交付门面不得再暗藏一套未计门窗。澳门货栈、福建居所与平户木屋的有限剧情空间由这些模块和材质组合；不承诺整城无缝漫游。若追求完整可进城镇，应另立范围和预算。

船体含结构、桅索、帆和必要挂点；独立炮身、炮架、桨、钩、斧在船具表另计，船壳包引用它们，不重复计数。火船、官旗船、缺帆与断桅采用同船壳的装载和可见性配置；通用断木另有一件道具。不是每艘故事里的船都要求新船型，也不按葡、荷、西、日国籍各复制一套相同船壳。

海面、岛屿高度场、云、粒子、帆morph、舵角、炮管后座和沉没物理均不当作独立烘焙基模或骨骼片段。生成人物实例、满船炮数量、颜色与建筑重复摆放也不乘算生产数。

## 验收与未完成边界

每个`existing.path`需是实际文件；`file-present`只说明存在，`procedural-source`说明有生成源码，`reference-only`说明仅作参照。它们与`productionStatus`的生产判断是两个维度，不能把存在直接替换为可发布。

正式制作时逐项确认形制资料、来源与许可、单位和朝向、材质、拓扑、UV、碰撞代理、挂点、LOD、骨骼／动画和导出可达性；船帆顶点与形变索引不得被导入器重排破坏。保持每实例独立骨架和现有状态／资源owner，不通过减少已接受船员或删效果制造性能通过。

本次交付是**有来源映射、可核算的资产生产方案**。没有新增83个模型，没有完成新动画或历史重建，也没有运行GPU／Godot或证明全游戏性能。具体页面与真实场景ID、既有来源和单项适配说明以JSON为准。
