# 舰船、人物与战斗 UI 深化审计

日期：2026-10-22。负责范围：`prototype/render-ships.js`、`prototype/ships.css`，23 页。保留墨青、铜金、宋体标题；本轮修改网页原型，不修改 Godot 或宣称已接入正式玩法。

## 共性整改

- 六名具名人物使用独立肖像 atlas，不再以同一船长立绘重复冒充：上排林阿旺、林阿禾、陈添；下排郑芝虎、安东、依斯迈。`prototype/assets/crew-portraits.png` 为 1536×1024、3 列 2 行，每格 512×512。名单、详情、岗位选择使用同一身份坐标。
- 一官本人使用专用 `prototype/assets/zheng-portrait.png`，替换旧 3D 卡通船长立绘；人物、装备与成长保持同一人。匿名招募者用职业徽，雇用记录不冒充六名人物；盟船、独立舟主与暂离者不可直接派入本船岗位。
- 船图分为海贸福船、小渔船、西式商船，分别使用 `assets/fuchuan-inspection.png`、`assets/fishing-ship.png`、`assets/merchant-barque.png`。完整检视，不裁切船体；均是方案美术，不代表活动 3D 模型。
- 动作按当前银两、铺位、修理、材料、装填、火绳、弹药、已有支付、分配冻结等条件禁用，并给相邻文字原因和 `aria-describedby`。选择按钮给出 `aria-pressed`，焦点保持清楚。
- 23 页的 4 个声明预览状态均有自己的内容或控制差异；只读显示态不改写真实演示状态。可操作行为仍交给 app 的资源与记录处理。
- 货舱使用共享 `ui.cargoUsed(state)`、`state.cargoCapacity`，兼容默认 350 担，初态加权占用 194 担。背包保留随身器物和凭据，大宗贸易货不混入背包。
- 桌面、多列压缩和窄屏均有结构重排。船员表只隐藏次要职责列，保留身份、所属和选择；甲板在窄屏改为可达的岗位格，避免缩成难点的微型图。
- 战斗画面按 `data-page='battle-hud'` 独立限定 flex 高度，消除共享内容最小高度与场景高度不同造成的下方黑带；捕获 / embed 模式占满画布，导航紧随场景。

## 验证记录与边界

- `rtk proxy node --check docs/design/game-ui/prototype/render-ships.js`：通过。
- `rtk proxy node tools/verify-game-ui-prototype.mjs`：本轮先取得 72/72 页面与 renderer、24 项通过；最终集成复跑遇到并行修改中的 `render-world.js: Unexpected end of input` 及尚未落盘的 `world.css`，因此最新全站结果为 51/72、18 项通过 / 6 项失败。失败源均在本模块之外，需主任务等其他模块落盘后重跑。该工具会更新既有 `prototype/verification.json`。已有 72 张预览文件的存在性不等于本轮浏览器重新截取。
- 本模块最终 VM：正常与声明状态 115 次，另加 3 船型、6 人物、资源不足和空舱等分支，共 140 次渲染；0 undefined / NaN、0 悬空页面导航、0 缺失图像路径；23 页各自的 4 个声明状态均有不同 HTML 输出。
- 额外门禁：船厂银两为 0、改装银两为 0、招募满员、装填忙碌、两舷无弹、战利已分配，都产生 disabled 与相邻原因。
- 六人肖像、三类船图的来源与最终像素采用由主任务记录；本文件不代替生成来源记录。所有资源、抽调、订造、抛货和工资行为由主任务 app handler 统一落账。
- 浏览器截图、窄屏真实布局、全部点击回归由主任务继续验收。VM 与静态检查不证明实际像素无缺陷，也不代表 Godot 正式玩法通过。

## 复核补充：抛货归属与名册密度

- 目视 `prototype/evidence/detail-pass/crew-roster.jpg`：1440 宽全页约 1340 高，右栏约 448px 正方肖像加正文将卡片拉长到约 718px，确实造成底部多余高度。6 行表格不是主要原因。
- 桌面 ≥1101px 将右栏与肖像均限 320px，正文区缩紧；≥741px 的表行头像 44px、上下内边距 11px、正文仍 14px。手机原有自然滚动与 110 / 140px 侧像布局保持。目标是去除审阅壳后约 1000–1100px；最终高度由主任务重新捕获验证，本记录不把估算当测量。
- 归属统一读 `state.cargoOwnership?.[good] === 'disputed'`，未设置默认自有。争议预览只在只读显示态给瓷器附 disputed；实际任意货品的 disputed 会同时反映在舱单、侧栏归属和抛货禁用原因。
- 专项 VM：默认自有瓷器、明确 owned 瓷器均可抛；disputed 瓷器与 disputed 木材均禁用。四项通过；名册默认保留全部六行。`node --check` 通过。
