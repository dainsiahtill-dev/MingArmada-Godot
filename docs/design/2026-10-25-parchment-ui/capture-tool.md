# 本轮原生 UI 捕获工具

`tools/capture-parchment-ui.gd` 仅做本次纸本界面的 GPU 截图、输入操作和布局观察。产品 UI 未由本工具改写。先完成纹理导入及所有实施者的主题修改，再按组运行；同一时刻只有一个捕获实例。

## 运行合同

- 必须显式 `--group=menu|mingqi|legacy|naval|catalog|practice|auxiliary|all`。
- 必须显式新 `--output=res://docs/design/2026-10-25-parchment-ui/evidence/<ascii-lowercase-name>`；只接受一个新叶目录，不接受路径穿越、链接目录、设备别名、已有目录和历史证据路径。
- `user://` 必须来自仓库 `Temp/parchment-ui-profiles/` 下的独立子进程 APPDATA；同时设置子进程 LOCALAPPDATA，不修改系统／用户环境。`PARCHMENT_ORIGINAL_APPDATA` 保留启动器进入前的 APPDATA，供真实玩家槽的只读哈希检查。
- 原槽 3 类文件及 `.backup/.rollback/.staged` 共 12 项前后比对。测试使用 `user://tests/parchment-ui-<PID>-*.json`。独立槽文件保留，不执行磁盘清理；场景正常释放。
- 截图必须是非 headless。正常结束和内部看门狗（单组300秒，all组1200秒）均退出自己的 SceneTree，不终止其他进程。
- FileDialog 使用 Godot 的嵌入子窗口，以捕获实际主题；不声称原生操作系统文件选择器已经验证，也不选择／导出文件。

## 证据与检查

每个状态生成 PNG 与 JSON：真实 GPU／引擎／viewport、当前场景、focus owner、可见控件数量、面板与按钮矩形、文字和颜色、滚动／裁切信息、装饰鼠标过滤值。完整报告 `capture-result.json` 记录动作、错误、前后槽状态和运行开始时的本组产品依赖／素材源哈希。运行结束再次核对这些源哈希，防止把并发改动混入一个完成结论；未涉及的其他组可独立修改。

`unclippedOverflow` 是待视觉审阅的候选，不直接判定产品错误。它排除被祖先裁切的滚动内容，但嵌入 Window、装饰背景或实际允许的子控件可能需要人工解释。必须打开 PNG 检查文字、对比、缺字、裁断和海面视野；不能仅依据控件矩形宣称视觉通过。

鼠标与键盘经 `Window.push_input` 进入实际 viewport GUI 分发，避免其他桌面窗口抢焦点导致事件投到错误窗口。记录其输入边界，不声称机器人在操作系统级移动了实体鼠标。真实按钮可见／启用／点击位置在视口内均有断言；显示状态和场景路由另做检查。
