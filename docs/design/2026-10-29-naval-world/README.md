## 文档维护规则

- 用户明确方向、主笔建议、待核史料、已经实现、已经验证分别记录。不能把“决定研究”升级为“已做完”。
- 新玩法先写：玩家想做什么、成立条件、输入资源、行动、收益、代价、对手如何应对、失败后的继续路径。
- 新船器先写：稳定 ID、原名／异名、资料时代和卷段、所属层（船体／动力／装具／任务）、证据状态、原创改编、模型与动画需求。
- 同名异物分开，异名同物不重复计算。陆战器械移植海上、图像复原和虚构兵种须明确标记。
- 研究进展追加日期与实际覆盖；未核图版、只见摘要、仅核目录要写明。历史数字不能直接当游戏平衡参数。
- 每次正式玩法修改同步更新对应设计、算法课题、验证记录和限制；小文案不制造算法课题。
- 测试失败保留条件和证据，写最小下一步；通过也只写实际验证范围。静态图不等于动态验收，局部实验不等于完整游戏。
- 最初阶段交付文档，后续已建立船员独立课题。实现继续遵守[研究工作流](../../research/README.md)，不把候选内容、设计条目或局部通过直接登记成正式玩法已验证。
