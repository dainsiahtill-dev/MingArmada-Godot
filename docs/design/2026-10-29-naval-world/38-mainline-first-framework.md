# 先贯通航程，再雕刻细节

2026-10-29。用户修订了开发顺序：先让全主线与各种玩法形成粗闭环，再深入局部表现。剧情可以按玩法学习需要修改，并逐渐升级难度；琉球、满剌噶及其他地区的王庭／地方人物要进入可互动故事。火势分区实战接线后移。全游戏目标仍 active。

## 本轮方向与当前事实

当前1650试玩只有两趟护粮；旧1661自由生涯另有送货、护航、剿盗、探查、接舷和海战＋陆战六章。父子24章、1646交棒、台湾T01—T10还只有设计。不能更换船长名字或把旧六章改标题后就称新主线完成。

先做统一主线执行框架：开局、章节任务、真实行动、成败结算、保损恢复、父子交棒、终章及保存恢复。复用现有操船／买卖／护送／海战／接舷／陆战执行器；新框架不能提供任意“判胜／跳章”的产品按钮。难度、人物与剧情结构先贯通，粒子、扑火动作、精细船型和复杂养成后置。

本稿的24章是现有设计的工作编号，不是不可改变的章数。新剧情按学习曲线重排，必要时合并／拆分；稳定ID与迁移规则由执行数据负责。旧小说是取材，非强制逐段照搬的可玩脚本。

难度参数分为规则负担、同时目标、敌方构成、航程／资源压力四轴。首轮只设六档候选并记录由来；未做实战前不宣称已平衡。每次提高压力，先用剧情和可见情境解释为何需要旧技能。英雄缺席不能永久锁主线，失败不以免费舰队洗掉代价。

## 世界人物要改变航路

琉球以王府、通事、使臣、船户形成不同诉求。先救助／护送使船，获得有限引荐；会见决定可交付的粮货、回程安全与通商许可。可以委托可信代表去办，不把每个远港写成两位主角真实亲访。父篇建立的关系在子篇通过旧信与新履约重新取得信任，不自动继承忠诚。

满剌噶按年代区分港口控制者，柔佛王庭与港口商政另列。贸易协议、被扣货物、护送与采购可能互相牵制；接受某方军务会缩小另一份通行许可。地区不能只换背景颜色、把同一敌人升几级。吕宋、日本、暹罗、爪哇等先以少量差异化关系线进入，具体君主／官署与年代由专项查读核对。

人物会面、对白和私下交易可原创，明示戏剧重建；统治者、政权与港口易手不凭剧情需要乱写。参见同批 `docs/research/2026-10-29-regional-courts-and-ports.md`（尚在查读时不视为已完成）。

## 可执行内容合同 v1

内容文件：`assets/data/story_campaign/zheng_family_v1.json`。目录加载器：`game/domain/story_campaign/catalog.gd`。首批保持CH01—24，对应20个前期主任务＋台湾10阶段，共30个阶段；多个目标可以共存，但新规则量由章节限制。

顶层字段：`schemaVersion=1 / id=zheng-family-v1 / title / protagonists / chapters`。两名主角以 `zheng-zhilong / zheng-chenggong` 分开，不用显示名当身份。

每章字段：`id / order / act / title / protagonistId / year / regionIds / drama / teaches / reuses / difficulty / stages`。year为数值章年，日期未定者另在drama注明，不捏造月日。difficulty为`{tier:1..6,newRules:1,simultaneousObjectives:1..3,pressure:none|low|medium|high}`。drama为`{want,conflict,turn}`，均原创情境；regionIds使用既有REG-01..07。

每阶段字段：`id / mode / title / briefing / objectives / recovery / partialAllowed`。CH01..20阶段ID为`CH-01-S1`等，台湾严格T01..T10，归属CH21:T01..03、CH22:T04..05、CH23:T06..08、CH24:T09..10。mode为`sailing|trade|escort|naval|boarding|land|port|handoff`。objective为`{id,kind,target,required,unit}`，required正整数；kind为`arrive|deliver|trade-profit|capture|escort-arrived|recruit|charter|neutralize|protect|rescue|handoff|dispatch-returned|withdraw|stockpile|land-control|hold-blockade|accept-terms|evacuation-complete|port-handover`。recovery为非空可执行路径描述，不把失败写成自动赢。

目录仅描述目标；并不证明对应3D地区／玩法已经可用。完整通关必须由下述生产适配器逐项接通。

## 状态与执行责任

主线进度只拥有章节、阶段、尝试、唯一结果回执和当前人物；世界钱粮、船员、货物、舰船仍只由真实世界会话拥有。阶段通过真实业务／原生结果的适配事实观察目标，UI只发操作意图与确认结算。内容预览或合成fixture不能发到正式存档。

保护、库存和持续封锁等当前条件必须在实际世界结算事务中重新核验，不能把开局存活或曾经备足粮食当作最终完成。进度器的单调计数只记录已核验里程碑；生产适配器尚未接入前，它不保证世界条件一直成立。首次接舷可配置已受损目标与明确教学窗口，不能暗中要求玩家先掌握尚未教过的炮战。

先建立严格进度状态机、全30阶段合同和只读全章图，再逐类接实际执行器。纯进度合同通过只能称“框架验证”；全部30阶段真实可操作、失败可恢复、单存档从头到尾运行后，才称“主线粗闭环”。不以图已连通或CPU全绿代替这个验收。

交棒只发生在CH12结算后，记录一次来源与接收人物和真实交接清单；同一世界账不复制船货、不补血、不清债。保损继续读当前世界；检查点重试恢复整份世界与进度，不能旧船新赏金混用。章节跳年是明确转场，不高速跑几十年工资。

## 交付顺序与验收

1. 全主线内容与学习曲线落成机器可读数据，验证ID、30阶段连通、人物顺序、难度轴、地区和恢复出口；内容可随实际体验修改。
2. 进度状态机完成一次结算、失败／保损恢复、CH12交棒、T10完结、严格保存恢复的合同测试；仍标实验，不宣称实际玩法全通。
3. 用现有执行器逐类接真实行动，并按章节表填“可操作／待适配”状态。优先把所有玩法薄层接齐，不深挖某一场景。
4. 正式入口完成首章→交棒→台湾全部阶段→结局的真实GPU与输入验收，覆盖存档恢复和至少每类一次失败。之后回到美术、细节和局部平衡。
5. 同批同步介绍网页：进度、内容框架、未接玩法和实图分清；不把规划升级为已可玩。
